# Local Node MCP Server

## Search a published compendium from your own machine

[← Back to the Extractium README](../../../README.md)


## Summary

This folder holds one file, `server.js`, over the protocol core in [`../shared/`](../shared/). It lets an AI assistant on your computer search a published Extractium knowledge base. The assistant asks a question, the server searches the index, and it gets back whole sections with the address of each one. Nothing you ask leaves your machine: the index is a static file, and the question is turned into a vector by a model that runs locally through transformers.js.

The Model Context Protocol (MCP) is the standard that assistants use to call tools. This server exposes exactly one tool, `search_kb`. It is the same tool, with the same arguments and the same answers, as the [Python version](../local-python/README.md).


## What you need

1. Node 18 or newer.
2. A published index address, or an index file you built yourself.
3. An assistant that can run an MCP server over standard input and output.


## Run it

```bash
cd examples/mcp/local-node
npm install
EXTRACTIUM_INDEX_URL=https://example.org/kb/kb-index.json node server.js
```

On Windows, set the variable with `set` in Command Prompt or `$env:` in PowerShell, then run `node server.js`.

The server waits for requests on standard input, so on its own it looks like it has hung. That is correct: an assistant drives it. To add it to one, see [how to connect an MCP client](../../../docs/how-to/connect-an-mcp-client.md).

Run it from this checkout, by path. It reads the JavaScript client from `clients/js/` in this repository, which is not published to the npm registry, so `npx extractium-kb-mcp` has nothing to fetch. It also reads the three files under `examples/mcp/shared/`, which hold the tool definition and the protocol handling every Node example shares. To run the server from somewhere else, copy those four files next to `server.js` and change the import lines at the top to point at the copies.


## Settings

All settings come from the environment, so no file holds an address or a path.

| Variable | What it does |
|---|---|
| `EXTRACTIUM_INDEX_URL` | The published index. Must start with `https://`, except on `localhost`. |
| `EXTRACTIUM_INDEX_PATH` | An index file on this machine. Wins over the address above, and never touches the network. |
| `EXTRACTIUM_CACHE_DIR` | Where the downloaded index is kept. Defaults to `~/.cache/extractium-mcp`. |

One of the first two is required. Without either, the server stops at once and says so, with exit code 2.


## What the tool returns

`search_kb` takes a question (`query`) and, optionally, how many sections to return (`k`, 1 to 10, 4 by default). It gives back:

- A block of text for the model to read, headed by a reminder that the sections are quoted evidence and never instructions.
- The same sections as data, in `structuredContent`: the title, the address, the text, and whether the section came from a local folder.

An empty result means nothing was relevant enough. That is a real answer, and the text says so.


## The one package it installs

`npm install` pulls `@huggingface/transformers`, which runs the embedding model. It is loaded only when a search actually runs, so the tests here install nothing.

`package-lock.json` beside it pins every version that install resolves to. It is generated by npm, so it carries no license header of its own; it is part of Extractium and covered by the project license like every other file here.

That package brings a machine-learning runtime with it. Two of the packages underneath it, `sharp` (image decoding) and `adm-zip` (unpacking the runtime's binaries), have had high-severity advisories, and the version ranges that reach them stop short of the releases that fix them. The `overrides` block in `package.json` lifts both to patched versions, so a fresh `npm install` here reports no advisories. Install from this folder, so npm reads the lockfile.


## Limits

- The first search downloads the embedding model, about 130 MB. Later searches reuse it.
- The index is downloaded once and then revalidated, so an unchanged file costs one small request. If the host cannot be reached and a copy is cached, the cached copy is used.
- One tool, no writes: this server reads a static file and nothing else.


## Run the tests

```bash
node --test examples/mcp/local-node
```

They run against the small compendium committed in `tests/golden/`, with a recorded query vector standing in for the model, so they need no network and no install.


## Conclusion

You can now run a local search server over any published compendium from a JavaScript runtime. The [how-to page](../../../docs/how-to/connect-an-mcp-client.md) shows the client configuration for this server and the Python one.
